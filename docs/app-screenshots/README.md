# Aqwire Personal (`wiremo-personal-mob`) — visual reference

A screenshot-by-screenshot record of the **current** mobile app, captured before any redesign. It is documentation only: no UI, code or behaviour was changed to produce it.

## How these were captured

| | |
|---|---|
| App | `wiremo-personal-mob` @ `feature/ENG-1602`, Expo SDK 54 / React Native 0.81, version label **1.5.1 (1)** |
| Runtime | Expo Go 54.0.7 on an iOS 26.2 simulator (iPhone 17 Pro Max, 440×956 pt, portrait), light appearance, status bar fixed to 9:41 / full signal / full battery. The first ten captures (intro, login ×3, forgot-password ×3, sign-up ×3) were taken on an identical iPhone 17 Pro Max simulator running iOS 26.0 |
| Environment | `EXPO_PUBLIC_APP_ENV=local` (API base `http://localhost:8800`) served by a **throwaway mock API**, not the real backend |
| Data | Fictional (Maria Santos, `testuser@user.com`, test card 4242…). Billers and logos come from the repo's own `__mocks__/server/fixtures`; no real customer data, payments or provider calls were involved |
| Image format | PNG, 880 px wide (@2x of 440 pt; the originals were 1320 px) |

Things to keep in mind when comparing against a redesign:

- **States were produced on purpose.** Empty, loading, error, pending and failed states were forced by switching the mock API (empty lists, HTTP 500/401/409, slow responses, declined status). They show what the UI renders, not necessarily what production returns.
- **Some screens were opened by deep link** (`exp://…/--/<route>`) when the normal path needs a live provider or a missing entry point. The route column shows the real route either way.
- **Provider pages are placeholders.** 3-D Secure, PayPal, QR Ph and bank-authorization web views load a plain page served by the mock. Only the app's own chrome around them (header, Done / Cancel, spinner) is the real UI.
- **Dark toasts at the bottom** that read `[API Error] …` are React Native's development LogBox, not part of the production UI. A few captures where it was still visible are noted.
- **The simulator uses the hardware keyboard**, so the iOS software keyboard is never drawn; focused-field screenshots do not show how content is pushed up.
- **iPhone only, one size, one language.** Android, iPad, small phones, landscape, large text and dark theme (the app has none) were not captured.

**186 screenshots** in 8 folders, grouped into 18 user flows below.

## Screen flow map

Navigation as implemented today (file-based routes under `app/`; the tab bar is a custom floating bar with four tabs). Routes that exist but cannot be reached from the UI are marked ⚠.

```
App start  (app/index.tsx — guard: onboarding flag + stored token)
 ├─ first launch ........ Intro (/login/intro)
 │    ├─ Login ......... marks onboarding done, goes to Login
 │    └─ ⚠ Get Started .. commented out (Phase 2) → Onboarding carousel (/login/onboarding-flow) → Login
 ├─ no token ............ Login (/login)
 │    ├─ Forgot Password ─► Check Your Email (/reset-password/check-email)
 │    │      └─ emailed link (deep link) ─► Create New Password ─► Password changed ─► Login
 │    │      ⚠ Make Selection (/reset-password/otp-delivery-selection) and Enter Verification Code (/reset-password/verify-otp) exist but are not linked
 │    ├─ Sign Up (/signup) ─► Verify code (/verify) ─► Dashboard
 │    ├─ Login ok ─► Dashboard   (API may answer "needs OTP" ─► Verify code ─► Dashboard)

 ├─ Payment Methods card ─► Payment Methods tab    ├─ Recent Transactions ─► Transaction History / Transaction Details

Tab bar (always visible except while scrolling down):
 ├─ Home ........... Dashboard
 ├─ Bills .......... Bills hub (/bills): "Make a One Time Payment" ─► One Time Payments;  Auto Debit status card ─► All Enrollments / Enroll In Auto Debit

        ├─ card row ─► Card details (Set As Default / Delete ─► "Delete Payment Method?" modal)
```

## User flows

- **Login & session** — First launch intro, login (empty, validation, invalid, filled, rejected credentials), a login that is routed to OTP verification, and the forced-logout modal after a 401. (8 screenshots)
- **Sign up & email verification** — Sign Up form (empty, scrolled, validation, filled), the iOS Save Password prompt, and the six-box OTP screen that signs the user in on success. (9 screenshots)
- **Forgot / reset password** — Forgot Password → Check Your Email. The emailed deep link opens Create New Password, then Password changed. Two further reset screens (Make Selection, Enter Verification Code) exist in the code but are not wired into this flow. (8 screenshots)
- **Onboarding carousel (not reachable)** — Three-slide illustration pager. The intro screen's "Get Started" button is commented out for Phase 2, so this screen can only be opened by URL. (3 screenshots)
- **Email-change link** — Landing screen for the emailed change-email confirmation link. (1 screenshots)
- **Dashboard** — Home tab in its populated, empty (new user), error and loading states, plus the horizontal carousel interaction and the device Dark appearance. (9 screenshots)
- **Auto Debit overview & enrollment details** — Entry screen with the enrolments carousel and biller directory, the full list (all statuses, empty, search), and details for pending / active / cancelled enrolments. (12 screenshots)
- **Enroll in Auto Debit** — Merchant-driven enrollment: dynamic form → review → create → payment-method choice → card form → confirm and agree → 3DS web view → result screens → success receipt. (25 screenshots)
- **Bills hub, billers & saved bills** — Bills tab, One Time Payments (saved billers + biller directory with search and category chips), Saved Bills list, and their empty / loading / error states. (12 screenshots)
- **Add a biller** — Biller-specific dynamic form (empty, validation, partially filled, filled, with a legal terms checkbox). (6 screenshots)
- **Pay a bill with a card** — Biller Details / Pay (amount, fee, saved cards or one-time method) → confirm and accept terms → receipt (success / processing), failure handling, 3DS web view, card form, delete biller. (26 screenshots)
- **Pay with bank, QR Ph or PayPal** — Hosted-provider paths for one-time payments: bank picker, OTP, QR Ph and PayPal web views, and the result screens reached by the provider's return link. (17 screenshots)
- **Transactions** — Transaction History (list, empty, refreshing, partial error), filter sheet and date-range picker, and Transaction Details (successful / pending / declined / loading / error). (14 screenshots)
- **Payment methods wallet** — Saved cards list, card details (default and non-default), set-as-default, delete, add-card entry and the add-card form. (9 screenshots)
- **Notifications** — Notifications (empty), segmented tabs, overflow bottom sheet, and Notification Settings. Not reachable from the UI today (the header bell is commented out for Phase 2). (5 screenshots)
- **Profile & account settings** — Account Settings hub, Profile (loading, error, populated), Edit Personal Information, Edit Personal Address with pickers, and the Logout confirmation. (9 screenshots)
- **Account & security** — Account & Security hub, Change Email, Change Password (empty + validation) and the Deactivation / Deletion modal. (5 screenshots)
- **About, legal & contact** — About (version info), Terms & Conditions, Privacy Policy, Refund and Chargeback Policy, Licenses and Contact Us. (8 screenshots)

## Current visual language (reference for the redesign)

Read from `styles/common/colors.ts`, `typography.ts` and `styles/theme.ts`; confirmed against the screenshots.

- **Typeface:** Poppins (Regular / Medium / SemiBold / Bold), mapped onto React Native Paper variants. Font-size scale: 8, 10, 12, 14, 16, 18, 20, 24 pt (a few literals outside it, e.g. 17 and 34).
- **Brand colours:** aqua `#31D0DB` (primary buttons, links, active tab, focus outlines) and aegean blue `#3F5770` (titles, tab bar, dark panels). Supporting palettes for info (blue), success (green), error (red/orange `#EB3800`) and neutrals `#FFF → #595959`.
- **Components that repeat everywhere:** pill buttons (primary filled aqua, secondary pale-aqua, tertiary outlined), grey rounded section cards (`#F7F9FA`), outlined text inputs with floating labels, status pills (dot + label), skeleton blocks, a floating dark rounded tab bar, circular back button with centred title, snackbar at the top and a centred modal.
- **Layout:** one column, 16 pt outer gutters, light only (`userInterfaceStyle: "automatic"` but no dark palette).

## Regenerating or extending this set

The captures came from a throwaway mock API (not committed) that returns the repo fixtures plus fictional data and can be switched into empty / error / slow / pending / declined modes, a separate Metro server on port 8082 with `EXPO_PUBLIC_APP_ENV=local`, and Expo Go on a clean simulator. To retake a screen, run the app against any backend that returns equivalent data in the `local` environment and replace the PNG with the same file name.
